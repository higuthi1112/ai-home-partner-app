# AWS構築手順書 — AIホームパートナー

> **AWS担当の方へ。** この手順書は AWS を初めて触る前提で書いています。
> 上から順にやれば終わります。**飛ばさないでください**（特にステップ0）。
> 所要時間の目安は合計 **2〜3時間**です。
>
> 詰まったら、その画面のスクリーンショットを撮って共有してください。

---

## この作業のゴール

高齢者のタブレットから送られてくる「会話のテキスト」と「笑顔の写真」を分析して、
元気度が下がっていたら**ご家族のGmailへメールを送る**仕組みを作ります。

```
タブレット ──→ Lambda ──┬─→ Rekognition（笑顔の分析）
                        ├─→ Comprehend（会話の感情分析）
                        ├─→ DynamoDB（記録の保存）
                        └─→ SNS ──→ ご家族のGmail
```

**作るものは6つだけです。**

| # | サービス | 何をするもの | 所要 |
|---|---|---|---|
| 0 | **Budgets** | **お金の見張り番。最初に必ず作る** | 10分 |
| **0.5** | **Bedrock** | **AIの利用申請。★承認待ちが出ることがあるので今すぐ★** | **10分＋待ち** |
| 1 | DynamoDB | 記録をためておく表 | 10分 |
| 2 | SNS | メールを送る係 | 15分 |
| 3 | IAM + Lambda | 本体のプログラム | 60分 |
| 4 | Function URL | タブレットから呼べるようにする入口 | 15分 |

Rekognition は**作る必要がありません**。Lambda から呼ぶだけです。

> 🚨 **ステップ0.5（Bedrockの利用申請）だけは、今すぐ出してください。**
> 承認が即時のこともありますが、数時間かかる場合があります。
> 他の作業は承認を待たずに進められるので、**申請だけ先に出すのが最優先**です。

# ステップ0.5 — Bedrock の利用申請（★今すぐ出してください★）

> **このアプリの「AIが体調を判断する」部分は Bedrock を使います。**
> Bedrockは**モデルごとに利用申請が必要**で、承認が即時のこともあれば
> 数時間かかることもあります。**他の作業は承認を待たずに進められる**ので、
> まず申請だけ出してしまってください。

1. 検索欄に `Bedrock` → **Amazon Bedrock** を開く → **右上のリージョンが「東京」か確認**
2. 左メニューの一番下 **モデルアクセス（Model access）** を開く
3. **モデルアクセスを変更（Modify model access）** をクリック
4. **Anthropic の Claude Haiku**（いちばん安いモデル）にチェックを入れる
   - 見当たらない場合は Anthropic の欄にあるモデルをすべてチェックしても構いません
5. **次へ** → 利用目的の入力を求められたら記入する
   - 例: 「高齢者見守りアプリの試作。会話内容から体調の変化を検知する用途」
6. **送信** をクリック

**ステータスが「アクセスが付与されました（Access granted）」になれば完了です。**
「リクエスト済み（In progress）」のままなら、承認待ちなので他の作業を先に進めてください。

## ★モデルIDのコピー（これが重要）★

承認されたら、**そのモデルの正確なIDをコピーしてメモしてください。** ステップ3-5で使います。

1. Bedrock の左メニュー **モデルカタログ（Model catalog）** を開く
2. 承認された Claude Haiku を選ぶ
3. **モデルID** をコピーする

> 🚨 **ここが一番の落とし穴です。**
> 新しめのモデルは、素のモデルID（`anthropic.claude-...`）ではなく
> **「推論プロファイル」という別のID**（`apac.anthropic.claude-...` のように
> 地域名で始まる形）を要求することがあります。
> 間違えると `ValidationException` というエラーになります。
>
> **画面に表示されている文字列をそのままコピーしてください。**
> 推測で入力しないこと。両方の形式が表示されている場合は、
> **`apac.` で始まる方**（推論プロファイル）を使ってください。

✅ **完了の確認**: モデルアクセスが「アクセスが付与されました」になり、モデルIDをメモできた。

# ステップ1 — DynamoDB（記録をためる表）

1. 検索欄に `DynamoDB` → 開く → **右上のリージョンが「東京」か確認**
2. 左メニュー **テーブル** → **テーブルの作成**
3. 以下のとおり入力します。**大文字小文字まで正確に**（プログラムがこの名前を探します）

   | 項目 | 入力する値 |
   |---|---|
   | テーブル名 | `HomePartnerEvents` |
   | パーティションキー | `userId` — 型は **文字列** |
   | ソートキー | `sk` — 型は **文字列** |

4. **テーブル設定** で **設定をカスタマイズ** を選ぶ
5. **キャパシティモード** で **プロビジョンド** を選ぶ
   - Auto Scaling は **オフ**
   - 読み込みキャパシティー: **5**
   - 書き込みキャパシティー: **5**

   > 💡 なぜオンデマンドではないのか: プロビジョンドの 25 まではAWSの**永年無料枠**です。
   > 5 なら確実にその内側なので、文字どおり0円になります。

6. **テーブルの作成** をクリック → 状態が「アクティブ」になるまで1〜2分待つ

### TTL（古いデータの自動削除）の設定

このアプリは「記録は90日で自動的に消えます」とプライバシー説明をしています。
その約束を実装するのがこの設定です。

1. 作った `HomePartnerEvents` テーブルを開く
2. **追加設定** タブ → **有効期限 (TTL)** の **オンにする**
3. TTL属性名に `expiresAt` と入力（**この綴りでないと動きません**）
4. **TTLをオンにする** をクリック

✅ **完了の確認**: テーブルの状態が「アクティブ」、TTLが「オン」。

# ステップ2 — SNS（メールを送る係）

1. 検索欄に `SNS` → **Simple Notification Service** を開く → **右上が「東京」か確認**
2. 左メニュー **トピック** → **トピックの作成**
3. タイプ: **スタンダード**
4. 名前: `home-partner-family-alerts`（**この名前で作ってください**）
5. **トピックの作成** をクリック
6. **表示された「ARN」をメモしてください。** `arn:aws:sns:ap-northeast-1:123456789012:home-partner-family-alerts` のような文字列です。あとで使います

### メールアドレスを登録する

1. 作ったトピックの画面で **サブスクリプションの作成**
2. プロトコル: **Eメール**
3. エンドポイント: ご家族役のGmailアドレス
4. **サブスクリプションの作成** をクリック

### 🚨 ここが一番の落とし穴です

**登録しただけでは1通も届きません。**
ステータスが「**保留中の確認 (PendingConfirmation)**」になっているはずです。

1. 登録したGmailの受信箱を開く
2. `AWS Notification - Subscription Confirmation` という件名のメールを探す
3. **メール本文の `Confirm subscription` というリンクをクリックする**
4. SNSの画面に戻って**更新**を押し、ステータスが「**確認済み**」になったことを確認

> **メールが見つからないときは「迷惑メール」フォルダを見てください。**
> 迷惑メールに入っていたら「迷惑メールではない」を押し、
> 差出人 `no-reply@sns.amazonaws.com` を連絡先に追加してください。
> **これをやっておかないと、デモ当日に通知が迷惑メールに消えます。**

### テスト送信して確かめる

1. トピックの画面で **メッセージの発行**
2. 件名: `test`（**半角英数字で**。理由は下の注意書き）
3. 本文: `テストです`
4. **メッセージの発行** をクリック
5. **Gmailの受信トレイ（迷惑メールではなく）に届くことを確認**

> 🚨 **SNSの件名（Subject）には日本語が使えません。**
> 半角英数字100文字未満のみです。日本語を入れると送信が拒否されます。
> プログラム側では日本語を全部「本文」に入れることで回避しています。

✅ **完了の確認**: サブスクリプションが「確認済み」、テストメールが受信トレイに届いた。

# ステップ3 — Lambda（本体のプログラム）

## 3-1. 関数を作る

1. 検索欄に `Lambda` → 開く → **右上が「東京」か確認**
2. **関数の作成** → **一から作成**
3. 以下を入力

   | 項目 | 値 |
   |---|---|
   | 関数名 | `home-partner-api` |
   | ランタイム | **Node.js 22.x** |
   | アーキテクチャ | x86_64（初期値のまま） |

4. **関数の作成** をクリック

## 3-2. プログラムを貼り付ける

1. 下の方にある **コード** タブを開く
2. 左側のファイル一覧で `index.mjs` をダブルクリック
3. **中身をすべて選択して削除**（Ctrl+A → Delete）
4. このフォルダの `index.mjs` の中身を**まるごとコピーして貼り付け**
5. **Deploy** ボタン（コード欄の上）をクリック

> 💡 `npm install` も zip も要りません。1ファイルで完結するように書いてあります。

## 3-3. ★最重要★ 先に「テスト」を1回だけ実行する

**この確認を飛ばさないでください。** ここで問題が出るなら早く分かったほうが良いからです。

1. **テスト** タブ → **新しいイベントを作成**
2. イベント名: `check-import`
3. イベントJSONに、このフォルダの `test-events/06-badkey.json` の中身を貼り付け
4. **保存** → **テスト** をクリック

**期待する結果**: `"statusCode": 403` が返ってくる。

- ✅ **403 が返った** → プログラムの読み込みは成功しています。3-4へ進んでください。
- ❌ **`Cannot find package '@aws-sdk/...'` のようなエラーが出た**
  → **ここで作業を止めて、すぐにフロント担当へ連絡してください。**
  Lambdaに入っているAWS SDKのバージョンの問題で、別のやり方（zipでアップロード）に
  切り替える必要があります。手順を用意します。**自力で解決しようとしないでください。**

## 3-4. 権限（IAM）を設定する

Lambdaが Rekognition や DynamoDB を使えるように「許可証」を渡します。

1. **設定** タブ → 左メニュー **アクセス権限**
2. 「実行ロール」のところにある**ロール名のリンク**をクリック（IAMの画面が別タブで開きます）
3. **許可を追加** → **インラインポリシーを作成**
4. **JSON** タブに切り替える
5. このフォルダの `iam-policy.json` の中身を貼り付ける
6. **2か所ある `<ACCOUNT_ID>` を、自分のAWSアカウントIDに置き換える**
   - アカウントIDは画面右上のアカウント名をクリックすると出る12桁の数字です
   - 例: `arn:aws:dynamodb:ap-northeast-1:123456789012:table/HomePartnerEvents`
7. **次へ** → ポリシー名に `HomePartnerLambdaPolicy` と入力 → **ポリシーの作成**

> 💡 **`"Resource": "*"` があって不安になるかもしれませんが、これが正解です。**
> Rekognition と Comprehend は「このデータだけ許可」という細かい指定に対応していないAWSサービスです。
> DynamoDB と SNS のほうは、ちゃんと特定のテーブル・トピックだけに絞ってあります。

## 3-5. 環境変数を設定する

プログラムに「どのテーブルを使うか」「合言葉は何か」を教えます。

1. Lambdaの画面に戻る → **設定** タブ → **環境変数** → **編集** → **環境変数の追加**
2. 以下を追加します

   **必須**

   | キー | 値 |
   |---|---|
   | `TABLE_NAME` | `HomePartnerEvents` |
   | `TOPIC_ARN` | ステップ2でメモしたARN |
   | `APP_KEY` | **自分で決めた合言葉**（例: `hp-demo-2026-a7f3k9`） |
   | `ADMIN_KEY` | **別の合言葉**（例: `hp-admin-2026-x2m8p1`） |
   | **`BEDROCK_MODEL_ID`** | **ステップ0.5でコピーしたモデルID**（`apac.anthropic.claude-...` など）<br>★推測で入力せず、画面からコピーした文字列をそのまま貼ること★ |

   **お金の見張り（そのままでOK。開発中に足りなければ増やす）**

   | キー | 値 | 意味 |
   |---|---|---|
   | `DAILY_LIMIT_ANALYSIS` | `100` | 問診の分析の1日の上限回数（実運用は1日2回なので50倍の余裕） |
   | `DAILY_LIMIT_CHAT` | `200` | 雑談の1日の上限回数 |

   **任意（後から足せます）**

   | キー | 値 |
   |---|---|
   | `FAMILY_DASHBOARD_URL` | フロント担当から聞いたURL + `#family` |
   | `CHAT_PROVIDER` | `none`（雑談を使わない・既定）／ `gemini` ／ `bedrock` |
   | `GEMINI_API_KEY` | 雑談で Gemini を使う場合のみ。Google AI Studio で取得 |
   | `GEMINI_MODEL` | 雑談で Gemini を使う場合のみ（例: `gemini-2.0-flash`） |

3. **保存**

> 💡 **`DAILY_LIMIT_*` について。**
> AWS Budgets は「知らせるだけ」で支払いを止めません。
> **実際に使いすぎを止められるのはこの2つの数字だけ**です。
> 上限に達すると、Lambdaは AI を呼ばずに「今回はできませんでした」と返し、
> アプリ側は今までどおり会話を続けます（壊れて見えることはありません）。

> 🔑 **`APP_KEY` はフロント担当に共有してください。** タブレット側の設定に同じ値を入れます。
> なお、この合言葉は**秘密ではありません**（Webページに埋め込まれるので誰でも読めます）。
> いたずらリクエストを軽く弾くためのもので、本当の防御はステップ0のBudgetsと
> 次の「予約済み同時実行数」です。

## 3-6. 実行時間などの設定

1. **設定** タブ → **一般設定** → **編集**

   | 項目 | 値 | 理由 |
   |---|---|---|
   | メモリ | **512 MB** | 初期値128MBだと遅い |
   | タイムアウト | **30秒** | **初期値3秒では絶対に足りません。**<br>写真の分析＋AIの判断で10秒前後かかるため、余裕をもたせます |

2. **保存**
3. **設定** タブ → **同時実行** → **編集** → **予約済み同時実行を設定** → **2**
   - これは「万一暴走しても同時に2つまでしか動かない」という上限です。お金の保険になります。
4. **設定** タブ → **モニタリングおよび運用ツール** → ロググループのリンクを開く →
   **アクション** → **保持設定を編集** → **1週間**
   - ログは初期状態だと永久に残り続けます。1週間で十分です。

### ★届いたメールの文面を必ず確認してください★

>
> ※これは会話と表情から算出した目安であり、医学的な診断ではありません。

# ステップ4 — Function URL（タブレットから呼べる入口）

> **フロント担当から GitHub Pages のURLを受け取ってから**やってください。

1. Lambdaの **設定** タブ → **関数URL** → **関数URLを作成**
2. 認証タイプ: **NONE**
3. **「オリジン間リソース共有 (CORS) を設定」にチェックを入れる**
4. 以下を入力

   | 項目 | 値 |
   |---|---|
   | Allow origin | `https://ユーザー名.github.io` を追加<br>`http://localhost:5173` も追加（開発用） |
   | Allow methods | `POST` |
   | Allow headers | `content-type` |
   | Max age | `300` |
   | Allow credentials | **オフのまま** |

5. **保存**
6. **表示された関数URLをフロント担当に渡してください**
   （`https://xxxxx.lambda-url.ap-northeast-1.on.aws/` のような形です）

### 🚨 CORSの最大の落とし穴

**Allow origin には「オリジン」だけを書きます。パスを含めてはいけません。**

| | |
|---|---|
| ✅ 正しい | `https://yuusuke.github.io` |
| ❌ 間違い | `https://yuusuke.github.io/ai-home-partner-app/` |
| ❌ 間違い | `yuusuke.github.io`（`https://` が無い） |
| ❌ 間違い | `https://yuusuke.github.io/`（末尾のスラッシュ） |

**ここを間違えると、タブレットから呼んだときだけ動きません**
（Lambdaのテストでは成功するので原因が分かりにくい）。
「テストは通るのにブラウザからは動かない」ときは、**まずここを疑ってください。**

# トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 作ったはずのものが見つからない | **右上のリージョンが「東京」か確認。** 一番多い事故です |
| `Cannot find package '@aws-sdk/...'` | Lambdaに入っているSDKの問題。**自力で解決せずフロント担当へ連絡** |
| **`ValidationException`（Bedrock）** | **モデルIDが違います。** 素のIDではなく「推論プロファイル」（`apac.` で始まるID）が必要な場合があります。ステップ0.5に戻り、画面からコピーし直してください |
| **`AccessDeniedException`（Bedrock）** | モデルアクセスがまだ承認されていない。ステップ0.5のステータスを確認 |
| **AIの判定がいつも同じ / `message` が「今回はくわしく確認できませんでした」** | `BEDROCK_MODEL_ID` が未設定か間違っている。CloudWatchに `BEDROCK_MODEL_ID が未設定です` が出ていないか確認 |
| **`level` が必ず `LOG` になる** | 平常値がまだ3日分たまっていない。**先に `05-seed.json` を実行**してください（誤検知防止のための仕様です） |
| `AccessDeniedException`（その他） | IAMポリシーの `<ACCOUNT_ID>` を置き換え忘れ、またはポリシーの保存漏れ |
| `ResourceNotFoundException` | テーブル名の綴り違い。`HomePartnerEvents`（大文字小文字も一致させる） |
| `Task timed out after 3.00 seconds` | ステップ3-6のタイムアウト設定（**AIを使うので30秒**）をやり忘れ |
| **`本日の分析回数の上限に達しました`** | `DAILY_LIMIT_ANALYSIS` の上限。開発中に足りなければ環境変数の数字を増やす |
| メールが1通も届かない | **SNSの購読確認リンクをクリックしましたか？** ステータスが「確認済み」か確認 |
| メールが迷惑メールに入る | 「迷惑メールではない」を押し、送信元を連絡先に追加 |
| SNSで `InvalidParameter: Subject` | 件名に日本語が入っている。半角英数字のみにする |
| ブラウザから呼ぶと `CORS error` | **Allow origin にパスが混ざっていないか。** オリジンだけを書く |
| テストは通るがブラウザからだけ動かない | 同上。ほぼ100% CORSの設定です |

# 参考：作らなかったもの（聞かれたとき用）

仕様書には載っているけれど、今回**あえて作っていない**ものです。理由を添えておきます。

| サービス | 作らなかった理由 |
|---|---|
| **S3** | 写真をS3に置かず、Lambdaのメモリで分析してすぐ捨てる方式にしたため。<br>「24時間で削除します」より「**そもそも保存しません**」のほうが説明が強い |
| **Transcribe** | タブレット側のブラウザ機能が既に音声を文字にしてくれているため不要 |
| **Comprehend** | Bedrock の Claude が文脈ごと読んで判断するため不要になった。<br>Comprehendは「ポジティブ／ネガティブ」の3段階しか返さず、<br>「ちょっと痛い」と「すごく痛い」を区別できない |
| **Step Functions** | 順番に呼ぶ処理が Rekognition と Bedrock の2つだけなので、<br>Lambda1つで足りる。工程が増えたら導入する |
| **Cognito** | 今回のデモではログイン画面を見せないため。実運用には必要 |
